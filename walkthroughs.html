Walkthroughs

Eight task-oriented walkthroughs covering the most common ways the team uses the app. Each is short (3–7 steps), labeled with the audience it’s aimed at (everyone / lead / admin).

Need feature-level reference instead? The Reference Guide documents every tab, formula, and field in the app. These walkthroughs link to the relevant reference sections where extra context helps.
About the screenshots: Most walkthroughs include inline UI mockups labeled mockup. They approximate what you’ll see in the app and will be replaced with real screenshots as we capture them. If something looks slightly different in the live app, the live app is the truth — how we update these is documented in the appendix.

1. Your first day on the app

Everyone ~5 minutes

Sign in, get oriented, and find the things you’ll touch every day.

  1. Open the app and sign in.
    Go to the app URL your manager shared. Click Sign In in the top-right and authenticate with your City of Tucson ArcGIS Online account. Your name will appear next to the sign-out button when you’re in.
  2. Get oriented to the primary tabs.
    The top bar has the main sections of the app. Overview is the team intro page, My Work is your personal dashboard, Portfolio opens to Projects/Tasks lists, and Slideshow is the public lobby display. Admins also see Capacity, Issues, and Settings.
  3. Click My Work.
    This is where you’ll spend most of your time. The KPI strip shows your active projects, open tasks, overdue items, and weekly utilization. Below that you’ll see your week’s allocation, your projects, and your tasks. If your projects don’t appear, see the Name matching note in the My Work Tab reference.
  4. Set your preferences.
    Open ⚙️ Settings → Preferences. You can opt into the Slideshow tab, change your default landing tab, and turn on optional UI features. Changes save automatically.
  5. Bookmark the app and the User Guide.
    The Guide is reachable from any page via About / Help in the top-right. Bookmark both so you can return without retyping the URL.

2. Tracking your time on a task

Everyone ~3 minutes

Log time on tasks using the start/stop timer. Time tracking has to be enabled for you first by a team lead in Settings.

  1. Open My Work.
    If a ⏱️ Time Tracking panel appears between the KPI cards and the My Week section, you’re enabled. If you don’t see it, ask a team lead to turn it on for you in Settings.
  2. Pick a task from the dropdown.
    The dropdown lists your In Progress, Waiting for Response, and On Hold tasks. Pick the one you’re about to work on.
  3. Click ▶ Start.
    The elapsed time begins counting up. A green pulsing indicator confirms the timer is active. You can start timers on multiple tasks at once if you’re context-switching.
  4. When you take a break, click ⏸ Pause.
    The entry saves and a green ▶ Resume button appears in today’s log so you can pick the same task back up later. You can pause and resume as many times as you want; the entries sum to the right total.
  5. When you’re done with the work session, click ⏹ Stop.
    Hours are calculated from start and end times and your work schedule (overnight and weekend time is automatically excluded). The entry appears in Today’s Log below. Use the ✏️ Edit button if you need to adjust times or add notes.
  6. Forgot to start a timer?
    No problem — you can edit any entry retroactively, or use the manual entry form. See the Time Tracking reference for retroactive logging.

3. Updating one of your tasks

Everyone ~3 minutes

Change a task’s status, reassign it, or mark it complete.

  1. Find the task.
    The fastest way is from My Work → My Tasks. If it’s not there (e.g. it’s assigned to someone else but you need to update it), use the Portfolio → Tasks tab and search by name or task ID (e.g. T-220).
  2. Click the task to open its detail page.
    You’ll see the parent project, status, dates, assignees, description, and dependencies.
  3. Edit the fields you need.
    Change Status (e.g. Active → Waiting for Response), update Assignee, adjust Due date, or add notes in the description. Use working_due to track an internal target separate from the externally-committed due date.
  4. Mark complete when done.
    Set Status to Complete. The system records today as actual_end, which feeds the team’s throughput metrics (visible on the Slideshow tab).
  5. Click Save.
    Changes write to ArcGIS Online immediately. Other team members will see the update on their next refresh (the 🔄 Refresh toolbar button).

4. Submitting an idea

Everyone ~2 minutes

When you have an idea for a new project that doesn’t fit into existing work, submit it. A lead reviews it and either promotes it to Active or schedules it for later.

  1. Click 💡 Submit Idea in the toolbar.
    It’s in the top-right toolbar on every tab.
  2. Fill in the form.
    A short form opens. Required: Title, Description, Sponsor (whose decision it serves), Category. Optional but valuable: target partner department, anticipated effort, links to context.
  3. Click Submit.
    The idea is saved with status Idea and shows up in the Idea Review queue for leads.
  4. What happens next.
    A team lead reviews ideas regularly. They’ll either promote it to an Active project (assigning a contact and target dates), schedule it for a future quarter, or defer it with a comment explaining why. You’ll be able to see the status change when you next look at it.
  5. Tip — quality of intake.
    A short, specific description (one paragraph, three sentences) gets a faster review than a one-line stub. Include the decision the work will inform, not just the artifact.

5. Running a project from kickoff to close

Lead ~7 minutes (one-time setup; then ongoing)

The end-to-end flow for project leads: create the project, add tasks, work through phases, and close it out cleanly.

  1. Create the project.
    Either promote an existing idea (see Walkthrough 6) or click ＋ New Project from the Portfolio → Projects tab. Required: Title, Status (typically start at Scheduled or Active), Phase, Primary Contact, Partner Department, Category, target start and end dates.
  2. Add the team.
    In the project detail page, list contributors in the Team Members field. They’ll see the project on their My Work tab.
  3. Break work into tasks.
    Use ＋ New Task from inside the project. Each task gets an Assignee, a Status, and a Due date. Add Dependencies if a task must wait for another. Tasks with unresolved dependencies show a 🔒 in the Gantt view.
  4. Move through phases.
    Update the Phase field as the project progresses (Not started → Kickoff → Build → ...). Each phase has its own checklist of requirements; satisfy them in the project detail before advancing. Phase changes are visible on the team Slideshow throughput slide.
  5. Run a weekly check.
    Once a week, open your project, scan task statuses, look for tasks Waiting for Response for too long (those become “blockers” that show up on the team’s Health view), and update working_due if the schedule has slipped.
  6. Close the project.
    When done, set the project Status to Complete and fill in actual_end. Then go to Portfolio → 🔁 Project Review and complete a Project Review entry (what shipped, what we learned, links to artifacts).
  7. Verify it shows up in the throughput chart.
    The completion appears on the Slideshow’s 16-week throughput chart on the next data refresh. If your team’s 4-week rolling average ticks up, your project just helped move the needle.

6. Reviewing and promoting an idea

Lead ~3 minutes

Triage submitted ideas and turn the ones you accept into proper projects.

  1. Open 💡 Review Ideas.
    From the toolbar (visible to leads when there are pending ideas). The badge count shows how many are waiting.
  2. Read the idea and check the basics.
    Does it serve a real decision? Is the sponsor named? Is it a fit for one of our six service areas? If anything is missing, comment back to the submitter rather than promoting prematurely.
  3. Click Promote to Project.
    A pre-filled form opens. Set Status to Active or Scheduled (depending on whether it starts now or later), assign a Primary Contact, set Phase to Not started or Kickoff, and confirm the partner department and category.
  4. Save.
    The idea record is converted to a project. The submitter sees the status change when they next refresh.
  5. Hand off to the contact.
    Let the new project lead know they’re on the hook — from here, walkthrough 5 is the next step.

7. Capacity planning for the next quarter

Admin ~5–10 minutes

Look at the team’s allocation, find pinch points, and adjust before they bite.

  1. Open Capacity → Resources.
    You see one card per team member with their current-week utilization. Cards are color-coded: green for healthy (60–100%), amber for over (100–120%), red for very over (> 120%). Sort by most-allocated to find pinch points first.
  2. Open the allocation editor.
    Below the cards is a per-person allocation table. Click any cell to edit the allocation percentage. The total row at the bottom shows combined load — cells over 100% are highlighted.
  3. Switch to 📊 Forecast for the bigger picture.
    The Forecast tab projects 13 weeks out. The view is scoped to Data Intelligence only — affiliated collaborators from DA, DL, or Emerging Data Infrastructure plan against their own teams. Look for the Team Load chart — if combined allocated hours regularly approach combined capacity, you’re overcommitting. Per-person sparklines show whose load swings.
  4. Use the Capacity Planner below the forecast to find a candidate for a new project.
    Pick a Team (defaults to your own — switch to All teams or any of the four data teams), a Project size (S/M/L/XL), and a Role. The planner sorts everyone in the selected team by their earliest plausible start week, with timeline bars showing where the new project would fit alongside existing allocations. People at capacity for the whole window appear at the bottom with the projects holding their time listed inline.
  5. Adjust where you can.
    Trade allocations between members, push Scheduled projects later, or flag specific projects to the requesting departments. The allocation editor saves changes immediately to ArcGIS Online.
  6. Communicate the result.
    If you re-scheduled or de-prioritized something, the project’s working_due update is automatic, but the partner department won’t know unless you tell them. A quick email beats a surprise.

8. Configuring the lobby slideshow

Admin ~3 minutes

Choose which slides display, in what order, for how long — and share the public URL.

  1. Open ⚙️ Settings → System → Slideshow.
    Admin-only. The editor lists every available slide with controls for enable, order, and per-slide duration override.
  2. Toggle slides on or off.
    Uncheck slides that aren’t telling a useful story right now (e.g. an empty Priority slide while the team rebuilds the priority taxonomy). Disabled slides simply don’t appear in the rotation.
  3. Reorder with the ▲▼ arrows.
    Lead with whatever you most want lobby visitors to see first. The throughput chart is a good opener for a “team is shipping” feel; the team intro is a strong opener for “who is this team?”
  4. Tune durations.
    Default is 15 seconds. Slides with more text or smaller numbers (categories, deadlines) read better at 20–25; slides with one big number (snapshot, throughput) read fine at 10–12. Override per-slide in the right column; leave blank to use the default.
  5. Click Save changes.
    Saves to app_config.display_config — the next time anyone opens the Slideshow tab they get the new config. No restart needed.
  6. Share the public URL.
    The Slideshow tab works without sign-in. Bookmark the deep link (the URL with #slideshow appended) on the lobby display computer; it’ll auto-load and start cycling.

9. Personalize the look of the app

Everyone ~3 minutes

Make the app feel like yours. Theme, font size, accent color, avatar emoji — everything in one place.

  1. Open ⚙️ Settings → Preferences.
    Personal settings are grouped into three sections: Appearance, Personal, and Layout & navigation. Changes save instantly and follow you across devices.
  2. Pick a theme.
    In Appearance → Theme, click any of the five preview cards: Tucson Classic (default), Sonoran Sunset, Desert Twilight, Pueblo, or Saguaro. One click retints any surface backed by the brand colors. Try a few — you can always switch back.
  3. Adjust the UI size if needed.
    In Appearance → UI size, type a percentage between 80 and 160 (default 100). Press Enter or click away to apply. The whole app scales — fonts and spacing together. Out-of-range values snap to the nearest valid number.
  4. Choose your accent color.
    In Appearance → Accent color, pick a swatch or open the custom color picker. Your own avatar tints across the entire app (header, project cards, task cards, person rows, etc.). Other people’s avatars are unchanged on your screen — they pick their own.
  5. Optional — pick an avatar emoji.
    In Appearance → Avatar emoji, type any emoji or pick one of the 20 preset chips. It replaces your initials wherever your avatar appears. Combines with your accent color (green circle + 🎯, navy circle + 🐢, etc.). Leave blank to use initials.
  6. Tune the celebratory bits.
    In Personal, toggle 🎉 Celebrate completions off if you don’t want a confetti burst when you mark a task or project Complete. The achievements panel on My Work can be hidden here too.
  7. If you’re color-blind, enable the safe palette.
    In Appearance → Color-blind safe palette, flip the toggle on. Status colors, priority badges, and alert indicators swap to an Okabe-Ito-derived palette that stays distinguishable for deuteranopia / protanopia.

10. Save and reuse a filter view

Everyone ~2 minutes

If you keep applying the same filter combination, save it. One click brings it back — or have it auto-apply every time you open the app.

  1. Set the filters you want to remember.
    On the Projects or Tasks tab, open the sidebar and pick a combination — e.g., Status = Active, ITD Team = Data Intelligence, Priority = High. Active filters appear as chips above the filter panel.
  2. Click ＋ Save current filters as view.
    The button appears at the top of the sidebar whenever any filter is active. A modal opens with a text input and a read-only summary of which filters will be captured — that way you know what you’re naming.
  3. Name it and click Save view.
    Max 40 characters. If a view by that name already exists, a warning shows and saving replaces it. Press Enter to submit or Esc to cancel.
  4. Apply it later with one click.
    Saved views show as chips at the top of the sidebar. Click a chip to reset all filters and apply that view. The active chip highlights in navy when the current filters match it.
  5. (Optional) Pin one as your default.
    Click the ★ on a saved-view chip. The star glows gold and that view’s filters auto-apply every time you open the app. Only one view can be default at a time — clicking the star on the current default clears it.
  6. Delete a view you no longer need.
    Click the × on the chip. A confirm dialog protects against accidents.

11. Tour your achievements

Everyone ~2 minutes

A quiet gamification layer celebrating your continued use of the tracker. No new data collected — everything’s computed live from what you already log.

  1. Glance at the slim panel on My Work.
    At the top of the My Work tab you’ll see a four-tile strip: 🔥 day streak, 🎯 tasks this month, ⏱ hours this week, 🏆 projects shipped. These are your near-term progress numbers.
  2. Click View all → for the full breakdown.
    It jumps you to the 🏆 Achievements tab in the top nav. The header shows your tracker tenure ("Tracker member since Jan 2026 · 14 months strong · 247 active days").
  3. Read your story.
    Six sections, top to bottom:
    • Right now — current snapshot.
    • Lifetime — never-resetting counters (hours, days active, longest streak ever, months strong).
    • This year — tasks closed, projects shipped, hours logged, weeks active.
    • Records — best week (most tasks closed in a single week), longest day, longest streak with date range, biggest project.
    • Breadth — how many task categories, tools, projects, and teammates you’ve worked across.
    • Milestones — 14 medals across Hours / Tasks / Projects / Streaks. Unlocked ones glow yellow; locked ones show a progress bar like "247 / 250 — so close".
  4. Know how the streak math works.
    A streak counts consecutive workdays (Mon–Fri) with at least one time entry. Weekends are skipped — neither required nor breaking. If today is a workday but you haven’t logged yet, the streak is still alive as long as yesterday had an entry.
  5. Hide it if it’s not your thing.
    In Settings → Preferences → Personal, toggle ✨ Show achievements panel off to hide the slim strip on My Work. The full Achievements tab stays available either way.

12. Add a project journal entry

Everyone ~1 minute

Capture observations, blockers, decisions — anything project-related that doesn’t belong in the description or structured fields.

  1. Open the project's detail page.
    From the Projects tab, click any project card or row. Scroll past the description, Definition of Done, Key Results, and any other structured sections.
  2. Find the Project Journal section.
    It sits below Reviewer Notes (if any) and above Time Logged. The textarea reads "Add a journal entry — observations, blockers, decisions, anything that doesn’t belong in the description."
  3. Type your entry and click ＋ Add Note.
    The entry is timestamped with the date+time, attributed to your signed-in name, and added to the top of the timeline (newest first).
  4. Read past entries.
    Entries persist forever and are visible to anyone signed in — they’re a project-level record, not a personal note. Older entries appear in reverse-chronological order below the input.
No edit or delete in the UI. Entries are append-only by design — the journal is meant to be a faithful log over time. If a stray entry needs correcting, an admin can edit the row directly in the Project_Notes AGO table.

13. Manage your week from My Week

Everyone ~2 minutes

The My Week section pairs each project allocation with the tasks you’ll touch on that project this week. Use it to spot projects with no actionable work and add tasks on the spot.

  1. Open My Work and scroll to 📅 My Week.
    Below the daily hours bar you’ll see one row per project you’re allocated to this week (hours, percentage, allocation bar).
  2. Read the per-project task list under each row.
    Pending tasks (Active, On Hold, Waiting for Response) are listed first, sorted by priority. Each row shows a status dot, the task title, an optional priority badge, the due date, and a status pill on the right (Active / On Hold / Waiting / ✓ Done). All columns line up so the pill column is easy to scan vertically.
  3. Check the "✓ Completed this Week" subheader.
    Below the pending tasks, a thin divider labelled "✓ Completed this Week" groups any tasks you completed during the current week (Mon–Sun). Done tasks render at 70% opacity so they sit visually subordinate to pending work. Tasks completed in earlier weeks aren’t shown here — they’re on the project detail page and counted toward your Achievements tab.
  4. Respond to a yellow-bordered row.
    If a project row has a yellow-amber left border and a warm-cream background, you have no actionable tasks assigned to yourself on that project (only completed ones, or none at all). A helpline below reads "⚠ No active tasks assigned to you on this project" with a ＋ Add a task button on the right.
  5. Click ＋ Add a task on the helpline.
    The New Task form opens pre-scoped to that project — you only need to fill in the task title, status, assignee, and due date. Save, and the yellow border on the row clears.
  6. Click a task to open it directly.
    Each task line is clickable and jumps to the task detail page where you can update status, log time, or add notes. Clicking the project row itself opens the project detail.

14. Find your issues & report a new one

Everyone ~2 minutes

The Issues tab opens scoped to your own issues by default. Filter to see other people’s, or click Report Issue to add a new bug or improvement request.

  1. Click the 🐛 Issues tab in the top nav.
    The header shows three filter controls: type (All / 🐛 Bugs / ✨ Improvements), status (Open / All / Done), and a Submitted by dropdown.
  2. Notice that Submitted by is pre-selected to you.
    On first open of the tab, the dropdown defaults to your signed-in name (labeled "<Your name> (me)"). You only see issues you submitted, and the type-pill counts reflect that scope.
  3. Switch to All users or a teammate's name.
    Use the dropdown to widen or narrow the list. The selection sticks for the rest of the session.
  4. Combine with type and status filters.
    All three filters are independent — e.g. set Status = Done + Submitted by = me to see what you've already resolved.
  5. Click ＋ Report Issue in the top-right to add one.
    Fill in title, type (Bug or Improvement), description, steps to reproduce (for bugs), and priority. Submit. Your name and the current date are recorded automatically; status starts at Submitted.
  6. Update an issue you submitted.
    Click any issue card to expand its actions. You can change status (Submitted → Accepted → In Progress → User Testing → Done) and edit fields. Submitters and admins can resolve/delete; everyone else gets a read-only view.

Updating walkthroughs

For whoever maintains this page (currently the team lead). The walkthroughs above are designed to be edited in place as the app changes.

Where walkthroughs live

Everything on this page lives in walkthroughs.html in the repo root. The sidebar TOC is at the top of the file inside <nav class="guide-nav">; the walkthrough content is inside <main class="guide-content">; the styling is in the page’s <style> block.

The deeper feature reference lives in a separate file, guide.html. If a walkthrough needs to send the reader for more context, link to a section in guide.html using its anchor (e.g. guide.html#mywork-tab).

Pattern for a single walkthrough

Each walkthrough is a <section class="wt-card" id="wt-..."> with three parts: head (title + audience badge + time), summary (one line), and an ordered list of steps.

<section class="wt-card" id="wt-your-id">
  <div class="wt-head">
    <h3>N. Title goes here</h3>
    <div class="wt-meta">
      <span class="wt-badge everyone">Everyone</span>  <!-- or .lead / .admin -->
      <span class="wt-time">~3 minutes</span>
    </div>
  </div>
  <div class="wt-summary"><p>One-line "what you’ll do."</p></div>
  <ol class="wt-steps">
    <li>
      <div class="wt-step-title">Click the X button.</div>
      <div class="wt-step-body">Why and what happens next.</div>
    </li>
    <!-- more steps -->
  </ol>
</section>

To add a new walkthrough: copy the pattern above, give it a unique id="wt-something", and add a matching link in the sidebar nav at the top of the file.

When the app changes — text updates

If you change a button label, rename a tab, or alter a workflow, update the matching walkthrough text. A useful rule of thumb: when you ship a code change that touches the UI, search walkthroughs.html for the old label and update it.

Quick check: If you renamed something globally, git grep for the old name across walkthroughs.html AND guide.html in addition to the source. Stale guide text confuses new team members faster than no guide at all.

Replacing a mockup with a real screenshot

Each illustration is currently an inline HTML/CSS mockup. When you have a real screenshot, swap it in:

  1. Capture the screenshot. Use the description in the figure’s caption as your shot list. Capture at full window width on a desktop browser; the content area is ~820px wide so 1200–1500px screenshots read cleanly.
  2. Save the image. Put it in a folder called guide-images/ at the repo root (create it if it doesn’t exist). Name the file using the data-img value on the mock div — e.g. data-img="primary-tab-bar" → guide-images/primary-tab-bar.png.
  3. Crop and compress. Crop tightly to the relevant UI region. PNG (or JPEG if no transparency / large screenshot). Aim for < 200KB per image.
  4. Swap the HTML. Replace the entire <div class="gh-shot-mock" data-img="...">...</div> with: 
    <img class="gh-shot-img" src="guide-images/primary-tab-bar.png"
     alt="Primary tab bar after sign-in">
  5. Clean up the caption. Remove the <em class="gh-shot-todo">...</em> "Replace this mock" text. Keep the Figure N.M. label and the descriptive sentence.
Tip — one at a time: Replace screenshots gradually. Eight walkthroughs spread across one workday is comfortable.

When a screenshot goes stale

UI changed and the screenshot no longer matches?

  • Recapture. Same filename overwrites the old file. Bump APP_VERSION for cache-busting (see below). Done.
  • Revert to a mockup. If the UI is mid-redesign, replace the <img> tag back to a <div class="gh-shot-mock" data-img="..."> with a fresh inline mock. The mockup badge in the corner makes the not-final-yet status obvious to readers.

Cache-busting

walkthroughs.html and guide.html are opened directly via window.open() without a ?v= query string, so browsers cache them aggressively. After updating either:

  • Bump APP_VERSION in src/constants.js per the project versioning convention (BUILD bump for guide-only updates; PATCH if you also fixed a related app bug).
  • Update the "Updated for v..." line in this page’s header to match.
  • Tell readers to hard-refresh (Ctrl+F5 / Cmd+Shift+R) when you announce changes.

Commit conventions

Walkthrough edits live in the same commit as the version bump:

v1.X.Y.NNNN — Walkthroughs: <what changed>

<Short paragraph: which walkthrough(s), what changed, why.
e.g. "Walkthrough 2 step 4 — Pause button now resumes
in the same task slot, not opens a new entry.">
