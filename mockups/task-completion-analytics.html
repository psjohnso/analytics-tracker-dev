Task Completion Analytics

Five options for a task-flow section on the Insights tab — how tasks move from start to done, where they stall, and how on-time delivery looks. Numbers are illustrative sample data. Most options run on existing task fields; one (time-in-status) has a real data gap, flagged below.

Where it slots: A new block on Capacity → Insights, alongside Duration Calibration and Planned vs Actual. The Team / Unit / Member filter row would scope all sections.

Option E

Time-in-status / bottlenecks

Average days a task sits in each status before moving on. The richest story — it surfaces where work stalls (often "Waiting for Response," i.e. blocked on a partner, not the team). But it has a real data dependency.

Data dependency: this needs per-task status-change history. The status_history layer is project-level only; task-level history exists only behind the FEATURE_TASK_HISTORY flag (task_status_history JSON) and may be thin or unpopulated. So this one is "build the capture first, then the chart" — unlike A–D, which run on data you already have.
How they compare:
  • A · Cycle time and C · Aging/overdue are the best value-per-effort — buildable today, and complementary (retro vs. live).
  • B · Throughput and D · On-time are easy add-ons from the same data; good as secondary panels.
  • E · Time-in-status is the most insightful but needs task status history captured first.
  • Bonus not shown: tasks also have hours (estimated) + hours_worked (actual), so a task-level estimate vs actual hours view is possible too — if those fields are actually being filled in. Worth a quick data check.
