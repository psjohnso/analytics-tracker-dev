Allocation Editor — form factor alternatives

Three layouts compared at representative scale. Same member, same data, same week window where possible. Real allocation grid markup is simplified for visual brevity but the room each layout has for the grid is honest. Each "browser" frame represents a 1100px-wide viewport.

Option 1
Dedicated full-page editor
"Edit Allocations" navigates to its own page. Sidebar holds person/capacity context. Grid gets the full main column — comfortably shows 8–10 weeks.

Pros

  • 8 visible weeks instead of 6 — no horizontal scrolling for typical edits.
  • Sidebar holds capacity context the modal can't fit (FTE, vacation balance, window utilization, legend).
  • URL is shareable — unit lead can send "review your allocations for Q2" link.
  • Survives future field additions (notes per week, project links, etc.) without re-cramping.
  • Save/Cancel pinned in header — always visible while scrolling.

Cons

  • Loses the "I'm in the Resources tab" context — needs a clear back path (breadcrumb at top does this).
  • Mildly more routing/state work than the modal — ~half a day.
  • If users edit allocations 10× a day, the navigation overhead adds up vs. a modal pop-up.

Pros

  • Roomier than modal — 6 weeks fit without horizontal scroll; could push to 7–8.
  • Resources tab still visible behind — preserves "I came from here" context.
  • Modern UX feel; familiar pattern.

  • If most users want 8+ weeks visible, this only marginally improves on the current modal.
Option 3
Inline expansion on the Resources tab
Click a member row to expand it in place — the grid unfolds below the row, full Resources-tab width. Other rows stay collapsed and visible.

Pros

  • Zero context switch — you stay on Resources where you started.
  • Full Resources-tab width for the grid — 7+ weeks comfortably.
  • Easy to flip through members in sequence — collapse Member B, expand Member C.
  • The surrounding util bars give you a "calibrate by neighbor" view while editing.

Cons

  • Vertical scrolling: the Resources tab gets tall with an expanded row.
  • Save semantics fuzzier — auto-save on apply? Discard if user collapses? Worth deciding upfront.
  • Re-imagining the Resources tab itself is bigger surgery than a route or panel swap.
  • Multi-edit can lead to "did I save Member A?" confusion if you expand multiple rows.

My take, restated. If quick weekly tweaks are the dominant use case, Option 2 (side panel) is the smallest reasonable improvement over today's modal — same flow, just a bit more room. If month-end reflection or unit-lead review is the dominant pattern (multiple people, multiple weeks per session), Option 1 (full-page) wins decisively because of the sidebar capacity context and the extra 2–4 visible weeks.

Option 3 (inline expansion) is technically interesting but has the most ambiguous interaction model — the save semantics get weird and the Resources tab itself needs a redesign to accommodate it. I'd punt on this one unless the team explicitly wants a tab-redesign anyway.
