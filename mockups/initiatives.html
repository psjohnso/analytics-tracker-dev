Notes for review

  • Sub-tab placement: Initiatives sits between Tasks and Project Review under the Portfolio primary tab.
  • The hero + KPI strip + timeline are the leadership-comm package. Any one of those three blocks should make sense screenshotted into a status report on its own.
  • The project list is the operational view. Drag-handle column on the left lets the owner re-order — that order drives the timeline's vertical sequence and the "1 / 2 / 3 / …" numbers everywhere they appear (e.g. activity feed).
  • Bidirectional attach: projects can be attached to an initiative from two places — the initiative editor / detail view (picker shown on screens 2 + 3) OR the project's own edit form (single-select "Initiative" picker). Either direction writes the same FK; surfaces stay in sync.
  • Status / progress are derived from the child projects, not manually set on the initiative. Edit form has "Status" only as an override for cases like pausing the whole thing on hold.
  • The breadcrumb on project detail (screen 4) is the one place this feature shows up on existing pages — everything else lives on the new Initiatives surface.
  • Not in V1: dependency arrows between projects (just visual ordering), many-to-many, sub-initiatives. Each could be Phase 2/3/4 if you decide you need them.
