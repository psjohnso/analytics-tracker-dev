Allocation Editor — window-driven project list

Instead of grouping by current status (Active vs Closed), the editor shows whichever projects were being worked on during the visible 6-week window. The project list flexes as the user clicks Prev / Next — projects appear when the window enters their active span and drop off when it leaves.

Inclusion rule: a project shows in the editor when its active span — start_date through (actual_end if Complete / working_due if mid-flight / end_date otherwise) — overlaps the visible window, OR the user already has a non-zero allocation on it in any visible week (insurance against projects with sparse date metadata). No more "Closed work" section; closed projects simply appear in their proper Leading / Contributing group when the window overlaps their lifetime.

How this differs from today:
  • No "Closed work" section. Projects in any state appear in Leading or Contributing based on the user's role. Status is shown via the chip on the row, not the section.
  • Visible project count is bounded. Most weeks you'll see 3–8 projects instead of "every project the person ever touched in the year." Lighter cognitive load.
  • Cells outside a project's active span stay editable, but get the hatched out-of-range styling — same convention we mocked up before. The team's "reflect on past weeks" practice still works at the closure boundary.
  • Project list updates on Prev/Next. Same render path as today — clicking ▶ already re-renders the grid; the only change is the row list is now filtered by window-overlap instead of by current status.
  • Scheduled (future-start) projects show up when the window reaches them. Lets the user pre-allocate as soon as a project is on the calendar.

A few questions worth pinning down before code:

  • Should we still auto-inject empty rows for projects where the user is contact / other_members but has no allocation yet, when the project's span overlaps the window? Currently the editor does this for active projects. I'd say yes, same behavior, just gated by the window-overlap rule.
  • What about projects with no start_date or end_date? Insurance fallback in the rule covers them — they show if the user has a non-zero allocation in any visible week. Better solutions need the dates filled in.
  • Section order — keep Leading then Contributing? Yes, but role on closed/canceled projects is a historical fact; sort within each section by date or status as you prefer.
