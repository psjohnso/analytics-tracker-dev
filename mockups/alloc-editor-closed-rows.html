Now: each closed project is its own row, editable for any week in the visible window. Past-week cells (within the project's active span) look just like Active rows. Future-week cells (after the project's end date) get the muted hatched background — visually telling you "you can still type here but the project was already closed by then."

Design decisions in this mockup:
  • Section is collapsible (chevron + count in header) — same UX pattern as "Contributing." Default state can be open or closed; suggest open when any closed-project row has a non-zero value in the visible window, otherwise collapsed.
  • Status chips reuse existing colors — blue for Complete, red for Canceled. Lets you scan the role distinction at a glance.
  • Out-of-range hatching — weeks after a project's end date show a subtle diagonal hatched background. The cell stays editable (the team's "reflect on past weeks" convention applies even right at the close boundary), but the visual cue tells the user "this week the project was already done."
  • No Auto-fill button on closed rows — auto-fill exists to populate forward; not relevant for finished work.
  • Role selector kept — same as active rows; rarely edited but consistent. Could lock if you'd rather; let me know.
  • Totals row math unchanged — sums every row (Lead + Contributing + Closed). Past weeks already worked this way via the rollup; per-row just makes the math more legible.
  • Visibility filter unchanged — closed projects only appear if the person logged time to them and that work falls inside the loaded 52-week window. Closed projects with zero contribution in-window stay hidden.
