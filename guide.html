Walkthroughs

Eight task-oriented walkthroughs covering the most common ways the team uses the app. Each is short (3–7 steps), labeled with the audience it’s aimed at (everyone / lead / admin), and links to the relevant feature reference further down the page for deeper context.

About the screenshots: Most walkthroughs include inline UI mockups labeled mockup. They approximate what you’ll see in the app and will be replaced with real screenshots as we capture them. If something looks slightly different in the live app, the live app is the truth — how we update these is documented in the appendix.

1. Your first day on the app

Everyone ~5 minutes

Sign in, get oriented, and find the things you’ll touch every day.

  1. Open the app and sign in.
    Go to the app URL your manager shared. Click Sign In in the top-right and authenticate with your City of Tucson ArcGIS Online account. Your name will appear next to the sign-out button when you’re in.
  2. Get oriented to the primary tabs.
    The top bar has the main sections of the app. Overview is the team intro page, My Work is your personal dashboard, Portfolio opens to Projects/Tasks lists, and Slideshow is the public lobby display. Admins also see Capacity, Issues, and Settings.
  3. Click My Work.
    This is where you’ll spend most of your time. The KPI strip shows your active projects, open tasks, overdue items, and weekly utilization. Below that you’ll see your week’s allocation, your projects, and your tasks. If your projects don’t appear, see the Name matching note in the My Work Tab reference.
  4. Set your preferences.
    Open ⚙️ Settings → Preferences. You can opt into the Slideshow tab, change your default landing tab, and turn on optional UI features. Changes save automatically.
  5. Bookmark the app and the User Guide.
    The Guide is reachable from any page via About / Help in the top-right. Bookmark both so you can return without retyping the URL.

2. Tracking your time on a task

Everyone ~3 minutes

Log time on tasks using the start/stop timer. Time tracking has to be enabled for you first by a team lead in Settings.

  1. Open My Work.
    If a ⏱️ Time Tracking panel appears between the KPI cards and the My Week section, you’re enabled. If you don’t see it, ask a team lead to turn it on for you in Settings.
  2. Pick a task from the dropdown.
    The dropdown lists your In Progress, Waiting for Response, and On Hold tasks. Pick the one you’re about to work on.
  3. Click ▶ Start.
    The elapsed time begins counting up. A green pulsing indicator confirms the timer is active. You can start timers on multiple tasks at once if you’re context-switching.
  4. When you take a break, click ⏸ Pause.
    The entry saves and a green ▶ Resume button appears in today’s log so you can pick the same task back up later. You can pause and resume as many times as you want; the entries sum to the right total.
  5. When you’re done with the work session, click ⏹ Stop.
    Hours are calculated from start and end times and your work schedule (overnight and weekend time is automatically excluded). The entry appears in Today’s Log below. Use the ✏️ Edit button if you need to adjust times or add notes.
  6. Forgot to start a timer?
    No problem — you can edit any entry retroactively, or use the manual entry form. See the Time Tracking reference for retroactive logging.

3. Updating one of your tasks

Everyone ~3 minutes

Change a task’s status, reassign it, or mark it complete.

  1. Find the task.
    The fastest way is from My Work → My Tasks. If it’s not there (e.g. it’s assigned to someone else but you need to update it), use the Portfolio → Tasks tab and search by name or task ID (e.g. T-220).
  2. Click the task to open its detail page.
    You’ll see the parent project, status, dates, assignees, description, and dependencies.
  3. Edit the fields you need.
    Change Status (e.g. Active → Waiting for Response), update Assignee, adjust Due date, or add notes in the description. Use working_due to track an internal target separate from the externally-committed due date.
  4. Mark complete when done.
    Set Status to Complete. The system records today as actual_end, which feeds the team’s throughput metrics (visible on the Slideshow tab).
  5. Click Save.
    Changes write to ArcGIS Online immediately. Other team members will see the update on their next refresh (the 🔄 Refresh toolbar button).

4. Submitting an idea

Everyone ~2 minutes

When you have an idea for a new project that doesn’t fit into existing work, submit it. A lead reviews it and either promotes it to Active or schedules it for later.

  1. Click 💡 Submit Idea in the toolbar.
    It’s in the top-right toolbar on every tab.
  2. Fill in the form.
    A short form opens. Required: Title, Description, Sponsor (whose decision it serves), Category. Optional but valuable: target partner department, anticipated effort, links to context.
  3. Click Submit.
    The idea is saved with status Idea and shows up in the Idea Review queue for leads.
  4. What happens next.
    A team lead reviews ideas regularly. They’ll either promote it to an Active project (assigning a contact and target dates), schedule it for a future quarter, or defer it with a comment explaining why. You’ll be able to see the status change when you next look at it.
  5. Tip — quality of intake.
    A short, specific description (one paragraph, three sentences) gets a faster review than a one-line stub. Include the decision the work will inform, not just the artifact.

5. Running a project from kickoff to close

Lead ~7 minutes (one-time setup; then ongoing)

The end-to-end flow for project leads: create the project, add tasks, work through phases, and close it out cleanly.

  1. Create the project.
    Either promote an existing idea (see Walkthrough 6) or click ＋ New Project from the Portfolio → Projects tab. Required: Title, Status (typically start at Scheduled or Active), Phase, Primary Contact, Partner Department, Category, target start and end dates.
  2. Add the team.
    In the project detail page, list contributors in the Team Members field. They’ll see the project on their My Work tab.
  3. Break work into tasks.
    Use ＋ New Task from inside the project. Each task gets an Assignee, a Status, and a Due date. Add Dependencies if a task must wait for another. Tasks with unresolved dependencies show a 🔒 in the Gantt view.
  4. Move through phases.
    Update the Phase field as the project progresses (Not started → Kickoff → Build → ...). Each phase has its own checklist of requirements; satisfy them in the project detail before advancing. Phase changes are visible on the team Slideshow throughput slide.
  5. Run a weekly check.
    Once a week, open your project, scan task statuses, look for tasks Waiting for Response for too long (those become "blockers" that show up on the team’s Health view), and update working_due if the schedule has slipped.
  6. Close the project.
    When done, set the project Status to Complete and fill in actual_end. Then go to Portfolio → 🔁 Project Review and complete a Project Review entry (what shipped, what we learned, links to artifacts).
  7. Verify it shows up in the throughput chart.
    The completion appears on the Slideshow’s 16-week throughput chart on the next data refresh. If your team’s 4-week rolling average ticks up, your project just helped move the needle.

6. Reviewing and promoting an idea

Lead ~3 minutes

Triage submitted ideas and turn the ones you accept into proper projects.

  1. Open 💡 Review Ideas.
    From the toolbar (visible to leads when there are pending ideas). The badge count shows how many are waiting.
  2. Read the idea and check the basics.
    Does it serve a real decision? Is the sponsor named? Is it a fit for one of our six service areas? If anything is missing, comment back to the submitter rather than promoting prematurely.
  3. Click Promote to Project.
    A pre-filled form opens. Set Status to Active or Scheduled (depending on whether it starts now or later), assign a Primary Contact, set Phase to Not started or Kickoff, and confirm the partner department and category.
  4. Save.
    The idea record is converted to a project. The submitter sees the status change when they next refresh.
  5. Hand off to the contact.
    Let the new project lead know they’re on the hook — from here, walkthrough 5 is the next step.

7. Capacity planning for the next quarter

Admin ~5–10 minutes

Look at the team’s allocation, find pinch points, and adjust before they bite.

  1. Open Capacity → Resources.
    You see one card per team member with their current-week utilization. Cards are color-coded: green for healthy (60–100%), amber for over (100–120%), red for very over (> 120%). Sort by most-allocated to find pinch points first.
  2. Open the allocation editor.
    Below the cards is a per-person allocation table. Click any cell to edit the allocation percentage. The total row at the bottom shows combined load — cells over 100% are highlighted.
  3. Switch to 📊 Forecast for the bigger picture.
    The Forecast tab projects 13 weeks out. Look for the Team Load chart — if combined allocated hours regularly approach combined capacity, you’re overcommitting. Per-person sparklines show whose load swings.
  4. Adjust where you can.
    Trade allocations between members, push Scheduled projects later, or flag specific projects to the requesting departments. The allocation editor saves changes immediately to ArcGIS Online.
  5. Communicate the result.
    If you re-scheduled or de-prioritized something, the project’s working_due update is automatic, but the partner department won’t know unless you tell them. A quick email beats a surprise.

8. Configuring the lobby slideshow

Admin ~3 minutes

Choose which slides display, in what order, for how long — and share the public URL.

  1. Open ⚙️ Settings → System → Slideshow.
    Admin-only. The editor lists every available slide with controls for enable, order, and per-slide duration override.
  2. Toggle slides on or off.
    Uncheck slides that aren’t telling a useful story right now (e.g. an empty Priority slide while the team rebuilds the priority taxonomy). Disabled slides simply don’t appear in the rotation.
  3. Reorder with the ▲▼ arrows.
    Lead with whatever you most want lobby visitors to see first. The throughput chart is a good opener for a "team is shipping" feel; the team intro is a strong opener for "who is this team?"
  4. Tune durations.
    Default is 15 seconds. Slides with more text or smaller numbers (categories, deadlines) read better at 20–25; slides with one big number (snapshot, throughput) read fine at 10–12. Override per-slide in the right column; leave blank to use the default.
  5. Click Save changes.
    Saves to app_config.display_config — the next time anyone opens the Slideshow tab they get the new config. No restart needed.
  6. Share the public URL.
    The Slideshow tab works without sign-in. Bookmark the deep link (the URL with #slideshow appended) on the lobby display computer; it’ll auto-load and start cycling.

Getting Started

Logging In

The Analytics Project Tracker uses ArcGIS Online OAuth 2.0 authentication. When you first open the application, you'll be redirected to the City of Tucson ArcGIS Online portal to sign in with your organizational credentials.

After successful authentication, your name appears in the upper-right corner. Your session lasts 120 minutes, after which you'll be prompted to re-authenticate.

User Roles

  • Standard User: Can view all tabs (Overview, Projects, Tasks, Resources, Forecast), create and edit projects and tasks, edit allocation percentages, and submit project ideas.
  • Admin: Members of the designated Team Leads group gain access to the Settings tab and can promote project ideas to active status. An Admin badge appears next to your name.

Browser Requirements

The application runs entirely in the browser as a single HTML page. It works with modern versions of Chrome, Edge, Firefox, and Safari. No software installation is required.

Navigating the Application

Tab Bar

The top navigation bar provides access to the main sections:

  • Overview: Dashboard with KPI summary cards showing project counts by status, active tasks, and team allocation overview.
  • My Work: Personalized dashboard showing your projects, tasks, allocations, and a project timeline. Appears after sign-in.
  • Projects: Full list of analytics projects with filtering, sorting, and detail views. Supports grid and list layouts.
  • Tasks: Individual task management with status tracking, due dates, and assignee information.
  • Resources: (Admin only) Team capacity planning with per-person allocation charts, utilization metrics, and an interactive allocation editor.
  • 📊 Forecast: (Admin only) Forward-looking capacity projection showing team availability and utilization trends.
  • 💡 Insights: (Admin only) Strategic reporting and data analysis views.
  • 🐛 Issues: Issue tracking and bug reporting for the team.
  • ⚙️ Settings: Personal preferences (all users) plus team member management, dropdown list configuration, AI features, and developer tools (admin only).

Sidebar Filters

The left sidebar provides filtering options on the Projects and Tasks tabs. Filter by project status, priority, category, partner department, ITD team, or team member. Task-specific filters (task status, task category, tool) appear when viewing the Tasks tab. Filters are independent between tabs — project status filters do not cascade to the Tasks tab.

Active filters appear as descriptive chips above the filter panel (e.g., "Status: Active, Scheduled" or "Member: Peter Johnson"), each with an × button to remove that individual filter. A "Clear all" link appears when multiple filters are active.

The team member filter defaults to showing only Data Intelligence team members. Check "Show N affiliated members" to include collaborators from other teams. A separate "Show former members" toggle reveals inactive team members.

View Toggle

On the Projects and Tasks tabs, switch between Grid (card-based) and List (table-based) views using the toggle buttons in the toolbar. Grid is the default.

Toolbar Actions

  • 🔄 Refresh: Reloads all data from ArcGIS Online, including projects, tasks, and resource allocations.
  • 💡 Submit Idea: Opens a simplified form for submitting new project ideas. Ideas enter with "Idea" status and must be promoted by an Admin.
  • 📋 Weekly Review: Filters tasks to show only those with activity in the current week.

Overview Tab

The Overview tab provides a high-level dashboard of the team's current workload. It displays summary KPI cards showing the number of projects by status (Active, On Hold, Complete, etc.), task counts, and overall team utilization. This tab hides the sidebar and view toggle to provide a clean dashboard layout.

My Work Tab (Logged-In Users)

The My Work tab provides a personalized dashboard that shows only your projects, tasks, and allocations. It appears in the tab bar after you sign in, and matches your ArcGIS Online display name to project contacts, team members, and task assignees.

At-a-Glance KPIs

Five cards at the top show your active project count, open task count, overdue tasks, tasks due this week, and your current week utilization percentage. Overdue and due-this-week counts highlight in red and yellow respectively when they need attention.

My Week

Directly below the KPIs, this section shows your allocation breakdown for the current week from the Resources data. It displays your work schedule type (5/8, 4/10, or 9/80), which pay period week you're in (A or B), your scheduled hours, and your RDO day if applicable. A daily bar shows your scheduled hours and work window (e.g., "8h / 7a–5p") for each day of the current week (Mon–Fri), with days off marked as "OFF." Below that, it shows hours and percentage allocated to each project, with a visual bar chart, plus your total allocated hours, capacity, and remaining availability.

Two-Column Layout

Below the KPIs and My Week sections, the remaining content is arranged in two columns. The left column shows your Projects, while the right column shows your Tasks. If any items need attention, a compact summary bar appears above both columns showing counts (e.g., "3 overdue · 1 due soon · 2 missing data").

Inline Attention Badges

Rather than a separate attention section, each project card and task row carries its own alert badges directly. Items with alerts sort to the top of their group by severity:

  • Red badge (e.g., "5d overdue") — Overdue items. Shows with a red left border. Active tasks with unresolved dependencies also get a red "Deps pending" badge.
  • Yellow badge (e.g., "Due in 3d" or "Ready to activate") — Items due within 7 days, or Future/Scheduled projects whose start date has passed.
  • Gray badge (e.g., "Missing: description, end date") — Incomplete project or task data. For Active tasks, missing start date and due date are flagged. Strategic alignment gaps (IT Initiative, City Initiative, WWC Practice) appear for authorized editors only.

Timeline (Gantt Chart)

A visual timeline showing your active, on-hold, and scheduled projects as horizontal bars spanning from start date to working due date. All open tasks for each project are shown nested under their parent project — your tasks appear at full opacity with bold labels, while other team members' tasks render at reduced opacity. Tasks are sorted with yours first, then others by due date. A legend at the bottom explains the visual distinction.

Tasks with unresolved dependencies (see Dependencies) are shown with a hatched/striped bar pattern and a 🔒 icon in the label. The chart includes month headers, a red "TODAY" marker, and red outlines on overdue bars. Click any label to open the detail page.

My Projects

All projects where you're the primary contact or a listed team member. By default, only Active, Scheduled, and Idea projects are shown. Click "Show more" to reveal On Hold, Future, Complete, and Canceled projects. Each row shows task completion progress, and projects where you are the lead are marked with a "Lead" badge.

My Tasks

All tasks assigned to you. By default, only "In Progress" and "Waiting for Response" tasks are shown — these are the ones that need active attention. Click the "Show more" button at the bottom to reveal Pending, On Hold, Complete, and Canceled tasks. Complete and Canceled tasks are further collapsed to the first 3 entries each.

Name matching: The My Work tab matches your ArcGIS Online display name to the data. If your projects or tasks don't appear, ensure your display name in ArcGIS Online matches the name used in the project/task records (e.g., "Peter Johnson" not "pjohnson").

Time Tracking

Time tracking is an opt-in feature that must be enabled per employee by a team lead in the Settings tab. When enabled, a "⏱️ Time Tracking" panel appears in the My Work tab between the KPI cards and the My Week section.

How It Works

The system uses a start/stop timer model. To log time on a task:

  • Select a task from the dropdown (shows your In Progress, Waiting for Response, and On Hold tasks).
  • Click "▶ Start" to begin the timer.
  • Work on the task. The elapsed time updates automatically.
  • Click "⏸ Pause" to temporarily stop the timer — the entry is saved, and a green "▶" Resume button appears in today's log so you can quickly restart the same task later.
  • Click "⏹ Stop" when you're completely done with a work session. Hours are calculated automatically from the start and end times.

You can run multiple timers simultaneously on different tasks. Active timers display with a green pulsing indicator and a live elapsed time counter. Pausing and resuming a task creates separate time entries that sum to the correct total — there's no limit to how many times you can pause and resume.

Overnight and weekend protection: If you forget to stop a timer, the system automatically caps the logged hours to your actual work schedule. For example, if you start a timer at 3:00 PM and stop it at 9:00 AM the next morning, it only counts 3:00–5:00 PM on day one and 8:00–9:00 AM on day two (based on your configured work hours), minus lunch — not the raw 18-hour span. Weekends and RDO days are excluded entirely.

Today's Log

Completed time entries for today appear below the timer controls, showing the task name, start/end times, and calculated hours. You can:

  • ✏️ Edit: Adjust start/end times and add notes (useful if you forgot to start or stop the timer).
  • 🗑 Delete: Remove an incorrect entry.

Daily and weekly hour totals are displayed above the log.

Enabling Time Tracking

In the Settings tab, the team members table includes a ⏱️ checkbox column. Check the box to enable time tracking for that employee; uncheck to disable it. Changes take effect immediately. Time entries already recorded are preserved even if tracking is disabled — they can be re-enabled at any time.

Pilot approach: Consider enabling time tracking for a few team members first to test the workflow, then roll it out to the full team once the process is established.

Projects Tab

Viewing Projects

Projects can be viewed in grid (card) or list (table) format. Each project shows its title, status, priority, category, assigned contact, start/end dates, and completion percentage. Click a project card or row to open its detail page with all fields, associated tasks, team members, and a timeline view. From the detail page, you can add a new task directly linked to the project using the "＋ Add Task" button in the Tasks section — the task form will open with the project pre-selected.

Creating and Editing Projects

To create a new project, an Admin must promote a submitted idea. Standard users can submit ideas through the "💡 Submit Idea" button. Once promoted, projects can be edited by clicking into the detail view — but only the project lead or an admin can edit, complete, or delete a project. The "Copy Summary" button is available to all users. Changes save directly to the ArcGIS Online projects feature service. Project names must be unique — the application prevents creating or renaming a project to a name that already exists (case-insensitive).

Choosing a category: The category field features a searchable dropdown — start typing to filter. If you're unsure which category fits, click the ✨ Help me choose button below the field. A short 2-question wizard will guide you to the right one.

Project Detail — Task List

The task list on a project detail page is divided into sections with distinct visual treatments:

  • In progress (green header) — Active, On Hold, and Waiting for Response tasks at full opacity.
  • Pending (gray header, 70% opacity) — Tasks waiting to start.
  • Complete (blue header, 60% opacity) — Finished tasks with muted styling.
  • Canceled (gray header, 60% opacity) — Canceled tasks with strikethrough titles.

Each section only appears if it contains tasks. Column headers (ID, Task, Status, Priority, Assignee, Due Date, Hours) are sortable — click a header to sort ascending, click again for descending. Sorting applies independently within each section. Tasks with dependency icons (🔒 deps pending, 🔓 deps resolved, ⛓ required by others) appear inline with the task title.

The batch editor lets you select multiple tasks via checkboxes and change their status, priority, or assignee in bulk. The status dropdown includes On Hold as an option.

Project Statuses

Projects follow this lifecycle:

Idea → Active → On Hold / Complete / Canceled

The "Future" status is also available for planned work not yet started.

Project & Task Dates

Both projects and tasks use a three-date model to track schedule changes over time:

  • Original End / Due Date — Set when the project or task is first created. This is the baseline and should not change once established — it represents the initial commitment.
  • Working Due Date — The current target completion date. Updated as scope or timelines shift. All overdue calculations, alerts, and deadline displays throughout the app use this date. On creation, it is automatically set to match the original due date.
  • Actual End Date — Automatically set to today's date when the status changes to "Complete." Represents when the work was actually finished.

Detail pages show all three dates side by side, with a red (moved) indicator when the working due date differs from the original. List views and cards show the working due date since that's the current target.

Tasks Tab

Tasks are individual work items associated with projects. Each task has a title, status, assignee, due date, and parent project reference.

Creating Tasks

Click the "＋ New Task" button in the toolbar or on the My Work tab. Required fields are Title, Status, Assignee, Project, and Description. Select the parent project, assign a team member, set dates, and provide a description.

AI-powered helpers: Category, Tool, and Project Size fields each have a ✨ Help me choose button — an amber pill that opens a guided wizard to recommend the best fit based on your answers.

Task Statuses

Tasks use the following statuses: Active, Pending, On Hold, Waiting for Response, Complete, and Canceled.

Date Requirements for Active Tasks

Setting a task to Active requires both a start date and a due date. This is enforced in three places:

  • Inline status dropdown — the dropdown reverts if dates are missing.
  • Batch update — the entire batch is blocked if any selected tasks lack dates.
  • Task form — the save is blocked and the missing date field highlights red.

Pending, On Hold, and Waiting for Response tasks do not require dates.

Filtering Tasks by Member

The member filter on the Tasks tab matches only the task assignee. Filtering by "James McGinnis" shows only tasks where James is the assignee — not all tasks on projects he leads.

Completing Tasks

There are several quick ways to mark a task as Complete without opening the edit form:

  • Task detail page: Click the green "✓ Complete" button in the header bar (next to Edit and Delete).
  • Project detail page: Each open task in the task list has a green ✓ button on the right side of the row.
  • My Work tab: Each open task in the My Tasks section has a green ✓ button.

Completing a task sets its status to "Complete" and records today's date as the actual completion date. A confirmation dialog is shown before the change is saved.

Resources Tab

The Resources tab is the team capacity planning hub. It shows how each team member's time is allocated across projects and whether they are over- or under-utilized.

Team Member Cards

The top section, labeled "Current Week Project Allocations," displays a card for each team member showing their name, role, and current week utilization percentage. The utilization badge is color-coded:

  • Green — Under 70% utilized (has capacity)
  • Amber — 70–90% utilized (getting busy)
  • Red — Over 90% utilized (at or over capacity)

Click a card to view that person's detailed allocation below.

Allocation Chart

A 20-week stacked bar chart shows allocation data, with each project in a different color. The capacity line (dark dots) shows the person's maximum project hours per week. A subtle highlight marks the current calendar week. Use the left/right arrows to scroll through the year.

KPI Row

Below the person's name, KPI cards show: current week utilization %, project capacity hours, allocated hours, number of active projects, and year-to-date total allocated hours.

Allocation Table

A table lists each project the selected person is allocated to, showing project status, a sparkline of recent allocation, and current week allocation percentage and hours.

Editing Allocations

Click "✏️ Edit Allocations" to open the allocation editor popup. This shows a grid of projects (rows) by weeks (columns). Enter allocation percentages (0–100%) for each project and week.

Tip: Projects are sorted alphabetically. Pressing Tab moves down the column (same week, next project) rather than across a row, making it easy to fill in one week at a time.

The total row at the bottom shows combined allocation — totals over 100% are highlighted in red. Click "✓ Apply Changes" to save. Changes are written to the ArcGIS Online allocations service and the view updates immediately.

Forecast Tab

The Forecast tab projects team capacity into the future based on current allocation patterns. It shows how loaded each person is over a configurable window (default 13 weeks from the current week), helping managers identify periods of over- or under-capacity and plan resource assignments accordingly.

What the Forecast Shows

The Forecast tab has three main sections:

  • Summary Cards: One card per team member, sorted by most available. Each card shows the person's average free hours per week over the forecast window, their average utilization percentage, and a sparkline of weekly utilization.
  • Team Load Chart: An area chart showing the entire team's combined allocated hours vs. combined capacity over the forecast window. This reveals when the team as a whole is approaching capacity limits.
  • Utilization Heatmap: A detailed grid showing each person's utilization (or available hours) per week, color-coded from green (low utilization) through amber to red (at or over capacity). This makes it easy to spot who has capacity and when.

How Future Availability is Calculated

The forecast uses a "snapshot" approach to project current workloads into the future. Here's how it works step by step:

Step 1 — Past/Present Weeks: Actual Data

For all weeks up to and including the current week, the forecast uses actual entered allocation hours — no estimation. These are the real values from the allocations service, so past data is always accurate.

Step 2 — Find the Snapshot Week

For each person, the system walks backward from the current week to find the most recent week where any allocations were entered (i.e., total allocation fractions across all projects are greater than zero). This becomes the person's "snapshot week."

For example, if James has allocation data entered through March 8, then March 8 is his snapshot week — even if the current calendar week is March 15.

Why a snapshot? This approach preserves the real allocation split (all project fractions summing to roughly 100%) from a single point in time, rather than mixing stale data from different weeks where projects may have changed.

Step 3 — Project Forward

For each project that had a non-zero allocation fraction in the snapshot week, the system carries that same fraction forward into every future week. So if James was 33% allocated to a project in the snapshot week, the forecast assumes 33% continues indefinitely.

The allocated hours for each future week are calculated as:

Future Allocated Hours = Snapshot Fraction × Project Capacity for that week

Note that project capacity can vary week to week due to absences — a future vacation week will show reduced capacity (and therefore reduced allocated hours) if the absence has been entered in the Settings tab.

Step 4 — Respect Project End Dates

If a project has an end date and a future week falls after that date, the allocation drops to zero for that project. This is how the forecast shows capacity "freeing up" when projects end — revealing future availability for new work.

Step 5 — Calculate Availability

For each person, for each week:

Availability = Project Capacity − Total Allocated Hours

Where Project Capacity uses the standard formula: (40 − Absence Hours) × 0.75 × Project Time %.

Utilization is then: Total Allocated Hours ÷ Project Capacity, capped at 125% for display purposes.

Worked Example

James McGinnis is 63% project-allocated with no absences. In his snapshot week (March 8), he has:

ProjectSnapshot Fraction
Safe Cities Dashboard33%
Parking Utilization Analysis25%
Water Quality Mapping20%

For a future week with no absences, his project capacity is 18.9 hours. The forecast calculates:

Parking Utilization0.25 × 18.94.73h

Total Allocated14.74h

Availability = 18.9 − 14.74 = 4.16 hours free. Utilization = 14.74 ÷ 18.9 = 78%.

If the Water Quality Mapping project ends in two weeks, then from that point forward James's forecast would show only 10.97h allocated and 7.93h free (58% utilization) — making him a good candidate for new work.

Limitations

Important: The forecast is a projection, not a plan. Keep these limitations in mind:
  • No allocation data = fully available: If a person has never had allocations entered (snapshot week is -1), their future shows as 100% available since there's nothing to project forward.
  • Future absences must be pre-entered: The forecast uses the capacity formula, which depends on absence data. If someone has a planned vacation next month but the absence hours haven't been entered in the Settings tab yet, the forecast won't reflect that reduced capacity.
  • Static snapshot: The forecast doesn't account for planned changes in allocation. If you know someone will move from Project A to Project B next month, the forecast won't reflect this until you actually update their allocations.
  • No new project predictions: The forecast only projects existing allocations forward — it can't predict when new projects will start consuming capacity.

Capacity & Utilization: Assumptions and Math

This section explains how the application calculates project capacity, allocated hours, and utilization. Understanding these calculations is important for interpreting the data on the Resources and Forecast tabs.

Core Assumptions

AssumptionValue / Explanation
Scheduled Work HoursComputed from each employee's daily start/end times and lunch duration: daily_hours = (end − start) − lunch, summed for the week. A 5/8 schedule (8am–5pm, 1hr lunch) yields 40 hours/week. A 9/80 schedule alternates between ~44 hours (Week A) and ~36 hours (Week B) across a 2-week pay period starting on Sundays.
Productivity Factor75% — Only 75% of available work hours are assumed to be productive project time. The remaining 25% accounts for meetings, email, administrative tasks, context-switching, and breaks. This is based on workplace productivity research showing the average knowledge worker is productively focused for roughly 6 of 8 hours per day.
Project Time %Each team member has a configurable percentage of their productive time dedicated to project work (e.g., 63% for a Lead Data Analyst). The remainder goes to operational duties, support, and overhead not tracked as projects.
AbsencesHours off per week (vacation, sick, holidays) are entered in the Settings tab. These reduce the scheduled hours before the productivity factor is applied.

The Capacity Formula

For each person, for each week:

Project Capacity = (Scheduled Hours − Absence Hours) × 0.75 × Project Time %

Where Scheduled Hours is determined by the employee's work schedule and which week of the pay period it is (Week A or Week B for 9/80 employees).

Worked Example — 5/8 Schedule, No Absences

James McGinnis has a 5/8 schedule, a project time allocation of 63%, and no absences this week:

StepCalculation
Scheduled hours40 hours (5/8 schedule)
Subtract absences40 − 0 = 40 hours available
Apply 75% productivity40 × 0.75 = 30 productive hours
Apply 63% project time30 × 0.63 = 18.9 project hours

Worked Example — 9/80 Schedule, Week B

If James were on a 9/80 schedule during Week B (36-hour week) with no absences:

StepCalculation
Scheduled hours36 hours (9/80 Week B)
Subtract absences36 − 0 = 36 hours available
Apply 75% productivity36 × 0.75 = 27 productive hours
Apply 63% project time27 × 0.63 = 17.01 project hours

Worked Example — With 1 Day Off

If James (5/8 schedule) takes 8 hours (1 day) off:

StepCalculation
Scheduled hours40 hours
Subtract absences40 − 8 = 32 hours available
Apply 75% productivity32 × 0.75 = 24 productive hours
Apply 63% project time24 × 0.63 = 15.12 project hours

Allocated Hours

When a team member is allocated a percentage to a project for a given week:

Allocated Hours = Allocation % × Project Capacity

For example, if James is allocated 50% to a project with 18.9 hours capacity: 0.50 × 18.9 = 9.45 hours. The total allocated hours for a person is the sum across all their project allocations for that week.

Utilization

Utilization measures how much of a person's available project capacity is actually allocated:

Utilization = Total Allocated Hours ÷ Project Capacity

Utilization is displayed as a percentage. 100% means fully allocated. Over 100% indicates overallocation. The color coding is:

  • Green — Under 70%
  • Amber — 70–90%
  • Red — Over 90%
Note: Both weekly_allocated and utilization are always computed client-side from the actual allocation data. This means they are always in sync with the latest edits, even before a page refresh.

Data Architecture

All data is stored in ArcGIS Online as hosted feature services. The application queries these services via the ArcGIS REST API using the authenticated user's OAuth token.

Feature Services

ServicePurposeKey Fields
projectsAnalytics project records with metadata, dates, status, and assignmentstitle, status, priority, category, contact, start, end
tasksIndividual work items linked to projectstitle, status, assignee, due_date, project_id, blocked_by
team_membersTeam roster with roles, capacity, schedule, and time tracking opt-inname, role, team, member_group, proj_pct, schedule_type, week1_hours, week2_hours, rdo_day, time_tracking, user_preferences
absencesPer-person, per-week time off recordsname, week_date, absence_hours
allocationsPer-person, per-project, per-week allocation recordsname, project, week_date, fraction, hours

Note: A weekly_capacity service also exists but is no longer queried by the application. All capacity values are computed dynamically from absences and team member settings.

Week Structure

The application uses a 52-week calendar year (2026) where each week starts on Sunday. Week dates are stored as Date Only fields in YYYY-MM-DD format. The week of January 4, 2026 is Week 1.

Data Flow

On page load, the application queries projects, tasks, team_members, absences, allocations, and app_config in parallel. The data is reconstructed into an in-memory structure used for all rendering. If the logged-in user has time tracking enabled, their time entries are also loaded. When changes are made (editing allocations, updating absences, managing team members, logging time), the application writes back to the appropriate REST service and updates local data immediately for a responsive UI.

Access Control & Permissions

Authentication

All users must authenticate through ArcGIS Online OAuth 2.0 (Implicit Grant flow, 120-minute token lifetime). Expired tokens trigger automatic re-authentication.

Group-Based Permissions

Administrative privileges (Settings tab access, Idea promotion) are controlled by membership in a designated ArcGIS Online group (Team Leads). This is managed entirely through ArcGIS Online group membership — no application-level user management is needed.

Read and write access to the underlying feature services is controlled through ArcGIS Online sharing settings. The following services must have editing enabled: projects, tasks, team_members, absences, allocations, app_config, and time_entries.

Updating walkthroughs

This is for whoever maintains the guide (currently the team lead). The walkthroughs above are designed to be edited in place as the app changes.

Where walkthroughs live

All walkthroughs live in guide.html, in a single Walkthroughs section near the top of <main class="guide-content">. The sidebar TOC entries are at the top of <nav class="guide-nav">. The CSS that styles them is the .wt-* and .gh-* rules in the page’s <style> block.

Pattern for a single walkthrough

Each walkthrough is a <section class="wt-card" id="wt-..."> with three parts: head (title + audience badge + time), summary (one line), and an ordered list of steps.

<section class="wt-card" id="wt-your-id">
  <div class="wt-head">
    <h3>N. Title goes here</h3>
    <div class="wt-meta">
      <span class="wt-badge everyone">Everyone</span>  <!-- or .lead / .admin -->
      <span class="wt-time">~3 minutes</span>
    </div>
  </div>
  <div class="wt-summary"><p>One-line "what you’ll do."</p></div>
  <ol class="wt-steps">
    <li>
      <div class="wt-step-title">Click the X button.</div>
      <div class="wt-step-body">Why and what happens next.</div>
    </li>
    <!-- more steps -->
  </ol>
</section>

To add a new walkthrough: copy the pattern above, give it a unique id="wt-something", and add a matching link in the sidebar nav at the top of the file. Numbering is informal — just bump the title number to fit the order.

When the app changes — text updates

If you change a button label, rename a tab, or alter a workflow, update the matching walkthrough text. A useful rule of thumb: when you ship a code change that touches the UI, ask "did I just invalidate any text in guide.html?" Search the file for the old label or feature name and update it.

Quick check: If you renamed something globally, git grep for the old name across guide.html in addition to the source. Stale guide text confuses new team members faster than no guide at all.

Replacing a mockup with a real screenshot

Each illustration in the walkthroughs is currently an inline HTML/CSS mockup. When you have a real screenshot, swap it in by following these steps.

  1. Capture the screenshot. Use the description in the figure’s caption as your shot list (e.g. "Primary tab bar after sign-in"). Capture at full window width on a desktop browser; the guide content area is ~820px wide so 1200–1500px screenshots read cleanly when scaled.
  2. Save the image. Put it in a folder called guide-images/ at the repo root (create the folder if it doesn’t exist yet). Name the file using the data-img value on the mock div — that string was chosen so file and HTML stay aligned. For example, data-img="primary-tab-bar" means save as guide-images/primary-tab-bar.png.
  3. Crop and compress. Crop tightly to the relevant UI region. Save as PNG (or JPEG if no transparency / large screenshot). Aim for < 200KB per image — the page loads many at once.
  4. Swap the HTML. Find the <div class="gh-shot-mock" data-img="...">...</div> block. Replace the entire mock <div> with an <img>: 
    <img class="gh-shot-img" src="guide-images/primary-tab-bar.png"
     alt="Primary tab bar after sign-in">
  5. Clean up the caption. Remove the <em class="gh-shot-todo">...</em> “Replace this mock” text from the <figcaption>. Keep the Figure N.M. label and the descriptive sentence.
Tip — one at a time: Replace screenshots gradually, not in a single big push. Each replacement is independent. Eight walkthroughs spread across one workday is comfortable.

When a screenshot goes stale

UI changed and the screenshot no longer matches? Two options:

  • Recapture. Same filename overwrites the old file. Bump APP_VERSION for cache-busting (see below). Done.
  • Revert to a mockup. If you’re mid-redesign and the screenshot will keep changing, replace the <img> tag back to a <div class="gh-shot-mock" data-img="..."> with a fresh inline mock. The mockup badge in the corner makes the not-final-yet status obvious to readers.

Cache-busting the guide

guide.html is opened directly via window.open('guide.html', '_blank') without a ?v= query string, so browsers cache it aggressively. After updating the guide:

  • Bump APP_VERSION in src/constants.js per the project versioning convention (BUILD bump for guide-only updates; PATCH if you also fixed a related app bug).
  • Update the "Updated for v..." line in this guide’s header to match.
  • Tell readers to hard-refresh (Ctrl+F5 / Cmd+Shift+R) when you announce changes — otherwise their cached copy hides the update.
